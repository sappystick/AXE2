# AXE2: clean-sheet 1-inch pulse-induction detector head

AXE2 is the RF2 head, split from the ARX / PHI-FOLD 233 repository (sappystick/ARX, branch claude/hopeful-bell-wms3xo) into its own repository.
- **Envelope:** D233 × 25.4 mm.
- **Coils:** a rim mono coil (26 turns, 333 uH) transmits and receives; two quadrupole receive boards give the bearing.
- **Shield:** the SH1 split-ring shield.
- **Display:** a 522-LED flex display under a clear lid.
- **Sectors:** HV, analog and digital.

Everything here is **MODELED / tool-checked**: there has been no fabricator DRC, no CAM review and no bench test.

## Commands
- `make tools` (= `scripts/bootstrap.sh`): installs and self-tests everything. It is also the SessionStart hook.
- `python3 run.py` (`make run`): runs only what is needed. That means steps that failed, whose inputs changed, whose outputs are missing, or whose dependency re-ran.
- Other runner modes:
  - `--failed`: only the steps that failed last time;
  - `--plan`: show what would run and why, run nothing;
  - `--step board:LR1 parity`: only the named steps;
  - `--cold`: everything;
  - `--list`: every step with its state and last result;
  - `--with-render` and `--with-studies`: include those optional groups.
- `python3 rf2/rf2_variants.py` (variant engine, every combination of design options with broken rules at their location; plugins in `rf2/variant_plugins/`, learning in `rf2/rf2_variant_learn.py`, knowledge base `rf2/rf2_kb.py`; see `.claude/skills/variants/SKILL.md`).
- `make route-test`: the router self-test. It rips 4 nets off MP1, reroutes them with A*, then runs KiCad DRC.

## Routing chain (per board, rf2/head/rf2_boards.py)
1. **Template / pre-routes.** The LED display is drawn by `rf2_ledgrid.py`. If nothing is left open, no router runs.
2. **Resume.** The last routed copper is copied onto the new build, except copper near pads that moved. Only items that KiCad DRC flags are deleted.
3. **Freerouting** (`src/pcb/freeroute.py`) routes the open connections only, with fan-out off on a resume. It has a stall watchdog: with `--stall` (180 s by default) and no finished pass, it stops and reports "stalled".
4. **A\* fallback** (`src/pcb/astar_route.py`): a deterministic grid router for whatever is still open. It keeps the clearance and rule-6 HV clearance and places vias only where they fit on both layers.

Every attempt is recorded in `out/<B>/<b>_check.json` under `route.strategies`. Never delete a routed `.kicad_pcb` by hand: it is the resume point.

## Rules (non-negotiable, carried over from ARX)
1. Change generators, never outputs by hand.
2. Every geometry claim is measured and becomes a check in `run.py`.
3. Performance numbers are MODELED and carry their assumptions. Never write "proven", "will detect" or "fabrication-ready".
4. A wrong earlier claim gets a row in `docs/CORRECTIONS.md`.
5. Eddy rule: no closed metal loop around the axis. Use open buses, split rings and hatched planes; every board's copper check tests this.
6. HV rule: coil flyback nets need ≥ 1.0 mm clearance and 630 V parts.
7. No fabricated datasheet facts. Mark a value UNVERIFIED, or cite the PDF in `data/datasheets/` and log it.
8. Run `python3 run.py` before and after every change, and report every number that moved.
9. Ask one question only when a decision changes the design; otherwise choose, state the choice and proceed.
10. Safety: no `rm -rf`, no glob deletes, no `pkill -f`; one background job at a time; never force-push.
11. Rule near-misses (owner, 2026-10-30): `docs/RULE_NEAR_MISSES.md` (step `rules`, `rf2/rf2_rules.py`) lists every rule a part fails by 10 % or less (BLOCKED), every rule the owner relaxed (RELAXED), and every pass with 5 % headroom or less (EDGE). Every report to the owner names these rows, so the owner can relax or remove a rule. Safety rules (rule 5, rule 6, absolute-maximum ratings) are reported, never relaxed automatically. Add a rule to `rf2_rules.py` whenever a new check with a numeric limit is written.
12. Integrations may reshape the layout (owner, 2026-10-31): when a new component or integration is adopted, the surrounding geometry, layout and structure may be redesigned too if that improves the whole machine; the old layout is not a constraint. Shelved options stay documented in `docs/INTEGRATION_MATRIX.md`.

## Conventions
mm / deg; z up from the underside of the skid; azimuth CCW from +x; heel (shaft side) at 178 deg. The display's spine frame: x' runs along the heel axis.
